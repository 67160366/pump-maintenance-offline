# หน้าจอ Pi 800×480 และผู้ช่วยถามข้อมูล

## ภาษาบนหน้าจอปัจจุบัน

ใช้คำไทยที่อธิบายการใช้งานโดยตรง: “ดูรายการถัดไป”, “ดูอัตโนมัติ”, “พักการอ่าน”,
“เริ่มรอบใหม่”, “ควรตรวจสอบเพิ่มเติม” และ “ยังไม่พบสัญญาณเตือน”
เรียก snapshot ว่า “รายการที่…” เพื่อไม่ทำให้เข้าใจว่าเป็นรหัสปั๊มจริง
คำตอบและข้อความเมื่อยังไม่มีข้อมูลบอกขั้นตอนที่ผู้ใช้ทำต่อได้

หน้าแรกไม่ใช้คำว่า Threshold/Template/Fallback/CSV replay/SQLite
รายละเอียดทางเทคนิคและ JSON ยังเปิดได้ใน “ข้อมูลเพิ่มเติมสำหรับผู้ดูแล”
สถานะข้อความมาตรฐานและ AI แสดงตามผลจริง ไม่เปลี่ยน fallback ให้ดูเหมือน AI สำเร็จ
อุณหภูมิ AI4I ในรายละเอียดแสดง °C แบบเดียวกับหน้าแรก; ค่า K ต้นฉบับใน facts/export
และอินพุตโมเดลคงเดิม สรุปบนหน้าจอใช้คำง่ายและไม่พิมพ์ค่าที่วัดซ้ำกับแผงด้านข้าง
ข้อความสรุปดิบและ prompt ของ LLM ไม่เปลี่ยนตามการจัดคำบนหน้าจอ

ตรวจ browser ขนาด 800×480 และ 390×844 ผ่านการดูข้อมูล คำถาม citation และดาวน์โหลดผล
ไม่มี console error หรือหน้าเลื่อนออกด้านข้าง ตัวอักษรช่วยอ่านและปุ่มมือถือปรับไม่ให้คำแตกหลายบรรทัด
ภาพหน้าจอปัจจุบันอยู่ ignored `evidence/plain-thai-*.png`; ภาพด้านล่างเป็นหน้าระบบรอบก่อน

## ข้อเสนอที่ทำเป็นหน้าระบบแล้ว

ใช้เว็บภายในเครื่องที่เปิดเต็มจอ แบ่ง 3 หน้าจากแถบนำทางด้านล่าง ไม่แสดงเครื่องมือทดลอง

## ช่องถามทำงานกับ LLM อย่างไร

```text
Snapshot CSV -> ML -> บันทึกผล + ค่าที่วัดใน SQLite
                                      ^
ผู้ใช้ถาม -> เลือกประเภทคำถาม -> Python query แบบกำหนดไว้ -> คำนวณคำตอบ -> แสดงหลักฐาน
             |                            |
             + local parser หรือ LLM       + LLM ไม่สร้าง SQL/ตัวเลข/รหัสเครื่อง
```

ตอนนี้รองรับสรุปข้อมูล รายการที่ ML เตือน อุณหภูมิสูงสุด และค่าล่าสุด
ไม่มีความจำบทสนทนาแบบอ้างคำถามก่อนหน้า ไม่มีการถามความรู้ทั่วไปหรือวินิจฉัยสาเหตุอิสระ
คำตอบปกติสร้างจากฐานข้อมูลโดยตรงและทำงานได้โดยไม่ต้องมี LLM

ถ้ามี llama.cpp/GGUF จริงและต้องการให้ LLM ช่วยอ่านคำถาม:

```bash
.venv/bin/python dashboard.py --llama-cli /absolute/path/llama-cli --gguf /absolute/path/model.gguf --llm-questions
```

LLM รับเฉพาะคำถามไม่เกิน 400 ตัวอักษร แล้วตอบ intent จาก grammar:
`summary / alerts / temperature / latest / unknown` ภายใน 10 วินาที
ไม่ส่ง CSV ทั้งหมดเข้า context ไม่อนุญาต SQL จาก LLM และไม่ใช้ผลแชตเปลี่ยนสถานะ ML
ถ้าไม่ผ่านรูปแบบ ขัดกับ keyword ที่รู้แน่ หรือ timeout ใช้ local parser แทน
คำตอบสุดท้ายและหมายเลขบันทึกยังคำนวณจาก SQLite เหมือนเดิม

บนหน้าจอ `local_data_query` แปลว่าไม่ได้เรียก LLM;
`local_llm_intent_validated` เท่านั้นคือ LLM เลือก intent ผ่านตรวจจริง
ส่วนสรุปรายแถวยังใช้ `pump.summarize` A/B ตามเดิม ทั้งสองงานไม่เปิด process LLM ซ้อนกัน
ต้องหยุด replay และรอแถวปัจจุบันเสร็จก่อนถาม มีผลให้ ML ไม่ต้องแย่ง CPU/RAM กับคำถาม

นี่เป็นข้อจำกัดของตัว replay สาธิตปัจจุบัน เมื่อเพิ่มการเก็บเซนเซอร์จริง ควรแยก collector
ให้เขียน SQLite ต่อเนื่องแม้กำลังสนทนา และให้คำถามอ่าน snapshot ของข้อมูลแบบ read-only
การเปิดแชตต้องไม่หยุดเก็บค่าจากเครื่องจักร ส่วน process LLM ยังคงจำกัดครั้งละหนึ่งงาน

ยังไม่มี GGUF หรือ Pi ที่เชื่อมต่อใน workspace นี้ ผลทดสอบ LLM router เป็น mock
ต้องทดสอบ grammar/flags/runtime และ latency จากอุปกรณ์จริงก่อนอ้างว่า LLM ทำงานแล้ว

## “วันนี้เครื่องไหนมีปัญหา” ต้องมีข้อมูลอะไร

ข้อมูล AI4I ปัจจุบันไม่มีรหัสเครื่องจริงและเวลาวัดจริง จึงตอบได้เพียง snapshot ใดในเดโม
ที่โมเดลเตือนหรือมีอุณหภูมิสูงสุด หากถามวันนี้จะบอกว่าไม่มีหลักฐานด้านเวลา
ไม่มีการใช้เวลาที่กด replay มาอ้างว่าเครื่องเกิดปัญหาในวันนี้

สำหรับข้อมูลปั๊มที่มีเวลาและรหัส:

- `Pump_ID`: ใช้ระบุเครื่องใน metadata เท่านั้น ไม่เพิ่มเป็น input ของ classifier เดิม
- `Measured_At`: คอลัมน์ CSV ทางเลือก ISO-8601 พร้อม timezone เช่น
  `2026-10-28T09:30:00+07:00`; เวลาไม่มี timezone ถูกปฏิเสธ
- `recorded_at` / event `at`: เวลาที่ระบบประเมินและบันทึก แยกจาก `measured_at`
- “วันนี้” ใช้วันของ Asia/Bangkok แล้วเลือกตาม `measured_at`; ไม่นับบันทึกที่ไม่มีเวลาวัด
- ต้องยืนยันหน่วยเซนเซอร์และกำหนดเกณฑ์ร้อนของแต่ละเครื่องก่อนตอบว่า “ร้อนเกิน”

AI4I แปลง Process temperature จาก K เป็น °C อย่างตรงไปตรงมาเพื่อแสดง/จัดอันดับ
ส่วน Temperature ของชุดปั๊มเดิมยังไม่ยืนยันหน่วย จึงไม่แสดงเป็น °C โดยเดาเอง
ผลเดิมไม่ได้ยืนยันกับปั๊มจริง การเพิ่ม timestamp ไม่เปลี่ยนโมเดลเดโมเป็นโมเดลใช้งานจริง

## การเก็บประวัติและขอบเขตคำตอบ

- SQLite ค่าเริ่มต้น `evidence/telemetry.sqlite3`; เปลี่ยนด้วย `--database /path/file.sqlite3`
- บันทึกเฉพาะเมื่อประมวลผลแถวเสร็จ ไม่เขียน DB ทุกครั้งที่หน้าเว็บ poll
- ปิดเปิดโปรแกรม/กดเริ่มใหม่ไม่ลบข้อมูลเก่า แต่สร้าง session ใหม่
- ค่าเริ่มต้นถามเฉพาะรอบนี้ เลือกทั้งหมดเพื่อดู session ก่อนหน้าใน dataset เดียวกัน
- จำนวนในคำตอบนับครบด้วย SQL; หลักฐานแสดงสูงสุด 3 รายการ ไม่ใช่นับจาก 3 แถวนั้น
- ประวัติแสดงล่าสุด 100 รายการเป็นหน้า ๆ; แชตเก็บข้อความบนหน้าจอสูงสุด 16 กล่อง
- `GET /api/records?scope=session|all`, `POST /api/ask` (`question`, `scope`)
- SQLite เป็นไฟล์ข้อมูลเฉพาะเครื่องและถูก ignore ไม่ push ข้อมูลเครื่องจริงขึ้น Git อัตโนมัติ
- ยังไม่มี retention policy อัตโนมัติ/ระบบ backup; สำรอง DB ตอนปิด server และกำหนด
  อายุข้อมูลก่อนใช้งานระยะยาว
