04 / ภายใน LLM · จากภาษาเป็นตัวเลข

ข้อความถูกเปลี่ยนเป็นเวกเตอร์
ก่อนเริ่มคำนวณ

Python ส่งคำสั่งและ facts ให้ Qwen2.5-0.5B ผ่าน llama.cpp ในเครื่อง

PROMPT / CHATMLคำสั่ง + ข้อมูล“เลือก A หรือ B”
พร้อมสถานะและค่าที่วัด
→
TOKENIZERแยกเป็น token IDstoken อาจเป็นส่วนของคำ
ไม่ใช่ 1 คำ = 1 token เสมอ
→
EMBEDDING LOOKUPหนึ่ง token → 896 ค่าเลือกเวกเตอร์จากตาราง
weights ที่ฝึกไว้แล้ว
xᵢ = E[token_idᵢ]

E คือ embedding matrix และ xᵢ คือเวกเตอร์ของ token ตำแหน่งที่ i

ระหว่างใช้งาน โมเดลคำนวณด้วย weights เดิม โดยไม่ฝึกใหม่จากคำถาม

05 / ภายใน LLM · คำนวณบริบท

Attention รวมข้อมูลจากบริบท
แล้วแปลงผ่าน Transformer 24 ชั้น

แกนคำนวณภายใน attention
Q = XWq · K = XWk · V = XWv
S = QKᵀ / √dₖ + causal mask
attention = softmax(S) V

Q = เวกเตอร์ที่ตำแหน่งนี้ใช้ค้นหา
K = เวกเตอร์สำหรับเปรียบเทียบแต่ละ token
V = ข้อมูลที่นำมารวมตามน้ำหนัก

Causal mask ปิดตำแหน่งอนาคต; RoPE ใส่ข้อมูลตำแหน่งให้ Q/K ก่อนเทียบความสัมพันธ์ สูตรด้านบนย่อ bias ออก

ตัวอย่างคณิตศาสตร์ 2 มิติ ไม่ใช่ activation ของ Qwen จริง
q = [1,0]
k₁ = [2,0] · k₂ = [0,2]

คะแนน = [1.414, 0]
softmax → น้ำหนัก ≈ [0.804, 0.196]

ถ้า v₁=[1,0] และ v₂=[0,1]
ผลรวมถ่วงน้ำหนัก ≈ [0.804, 0.196]

แต่ละชั้น: RMSNorm → Attention + residual → RMSNorm → SwiGLU + residual

GQA: 14 query heads / 2 KV heads · ภาพนี้ย่อหนึ่ง head; ของจริงรวม heads แล้วผ่าน output projection · สถาปัตยกรรมทางการ

ตัวอย่างสอน: vocabulary เพียง A / B / X และสมมติหนึ่งตัวต่อหนึ่ง token ไม่ใช่ logits จริง

สัดส่วนคะแนนภาษา ไม่ใช่โอกาสที่เครื่องจะเสีย
เมื่อเปิด mask จะคำนวณสัดส่วนเฉพาะ token ที่อนุญาต

ตัวอย่างนี้สมมติ facts ระบุ “ควรตรวจบำรุงรักษา” จึงรับ A; ถ้าเป็น B หรือผิดรูปแบบ จะ fallback

Adapter ใช้ temperature=0: เลือก token คะแนนสูงสุดที่อนุญาต ไม่สุ่มตามเปอร์เซ็นต์

Grammar คุมรูปแบบ แต่ Python ยังตรวจความสอดคล้องกับสถานะ ML

Output weights ผูกกับ embedding · ตัวจริง decode ต่อจนจบคำตอบและใช้ KV cache ภายในงานนั้น · แอปใช้ context 1,024 tokens
